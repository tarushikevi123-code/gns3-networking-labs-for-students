# Lab 03 – Ethernet Frames, IPv4, ICMP, TTL and Spoofing

## 1. Project Overview

This laboratory explores Ethernet frame construction, IPv4 packet encapsulation, ICMP communication, TTL behaviour and controlled source-IP spoofing using Linux, Python and Scapy.

The experiments are implemented in GNS3 using Linux-based network nodes and a Network Emulator. Wireshark and tcpdump are used for packet capture, inspection and analysis.

The laboratory focuses on understanding Layer 2 and Layer 3 addressing, Ethernet frame structure, packet encapsulation, next-hop forwarding and the behaviour of manually generated network packets.

**Note:** This is Lab 4 in the Hochschule Anhalt Computer Networks course and Lab 03 in this GitHub portfolio.

## 2. Project Objectives

- Understand the structure of Ethernet II frames.
- Differentiate between MAC addresses and IPv4 addresses.
- Generate custom Ethernet frames without an IP packet.
- Analyse EtherType values and Ethernet payloads.
- Construct Ethernet/IPv4/ICMP packets using Python and Scapy.
- Understand the relationship between destination IP addresses and next-hop MAC addresses.
- Investigate IPv4 TTL behaviour in local and routed communication.
- Observe ICMP Echo Request and Echo Reply behaviour.
- Demonstrate controlled source-IP spoofing in an isolated laboratory network.
- Analyse generated packets using Wireshark and tcpdump.
- Troubleshoot common packet transmission and encapsulation issues.

## 4. Implementation

### 4.1 Normal Ping and Packet Analysis

Analysed normal ICMP Echo Request and Echo Reply packets between hosts in the same network and across different networks.

Investigated Ethernet source and destination MAC addresses, IPv4 addressing, ICMP message types and TTL values.

### 4.2 Custom Ethernet Frame Generation

Developed a Python script using Scapy to generate Ethernet frames without IPv4 payloads.

An experimental EtherType (`0x88B5`) was used to identify custom laboratory frames.

The generated frames were captured and analysed in Wireshark to identify the Ethernet II header and raw payload.

### 4.3 IPv4 and ICMP Packet Construction

Used Scapy to construct custom Ethernet/IPv4/ICMP packets.

The implementation includes:

- Ethernet frame encapsulation.
- IPv4 source and destination addressing.
- ICMP Echo Request generation.
- Configurable TTL values.
- ICMP identifiers and sequence numbers.
- Automatic IPv4 and ICMP checksum calculation.

### 4.4 Next-Hop MAC Address Analysis

Compared communication with destinations in the same subnet and destinations in remote networks.

Investigated why the Ethernet destination MAC address represents the next-hop device, while the IPv4 destination address remains the actual destination host.

### 4.5 TTL Behaviour

Investigated the IPv4 Time To Live (TTL) field using different values.

Compared:
- TTL = 1 for a destination in the same network.
- TTL = 1 for a destination in another network.
- TTL = 64 for routed communication.

Observed packet forwarding behaviour and ICMP Time Exceeded responses generated by R2 when the TTL expired.

### 4.6 Controlled Source-IP Spoofing

Performed controlled source-IP spoofing inside the assigned laboratory network.

The experiment involved:

- Generating an ICMP Echo Request with a modified source IPv4 address.
- Retaining the actual Ethernet source MAC address.
- Observing the packet at the sender, destination and monitoring host.
- Analysing the behaviour of the Echo Reply.
- Investigating the ARP exchange for the forged source IP.

The experiment demonstrated how the target responds to the forged IPv4 source address while the Ethernet source MAC continues to identify the actual sender.

The experiment was restricted to the assigned laboratory network. ARP spoofing and ARP poisoning were not performed.

### 4.7 Docker Environment and Configuration Persistence

Used Docker containers within the GNS3 environment to run the Linux-based laboratory hosts.

Installed Python and Scapy inside the H1 container and created a virtual environment containing the required dependencies.

The scripts and virtual environment were stored inside:

`/root/lab2_frames_ip/`

Used `docker commit` to preserve the configured environment in a new image named `lab4-host:saved`.

Verified the saved image by starting a new container and checking that the scripts and Scapy environment were available.

## 7. Packet Analysis and Verification

Wireshark was used to inspect and verify:

- Ethernet source and destination MAC addresses.
- EtherType values.
- IPv4 source and destination addresses.
- ICMP message types and sequence numbers.
- IPv4 TTL values.
- IPv4 header and ICMP checksums.
- ARP requests and replies.
- ICMP Time Exceeded messages.
- Controlled source-IP spoofing behaviour.

The experiments demonstrated the difference between same-network and remote-network communication, including the role of the gateway as the next hop.
